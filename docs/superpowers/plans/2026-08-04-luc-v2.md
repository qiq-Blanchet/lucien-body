# Luc v2 实施计划

## 唯一规格

实现只以 `docs/clawd-v2-source-spec.md` 为功能与数值依据。该文件与用户提供的 UTF-8 MD 的 SHA-256 均为 `02FE905E4647AD8BCCBD608F74BB80A476E7288866E25763097DF5C1CA3B8185`。

用户追加的素材约束同样具有约束力：ZIP 对比板中被卡片引用的原始 `<svg>...</svg>` 必须按原 UTF-8 字节提取，不重画、不格式化、不修改 viewBox、样式、动画或颜色。90×90dp 由窗口和渲染容器实现。

规格标题的状态数量与明细不一致：完整优先级表明确给出 28 个具名 ID，素材板覆盖这 28 个；不虚构未命名的第 29 个状态。

## Task 1：规格与原件冻结

- 保存唯一规格的逐字节副本和 SHA-256。
- 从 ZIP 对比板的 37 张有效卡片提取原 SVG，并保存逐文件 SHA-256 清单。
- 第 26 张有效卡片 `clawd-collapse-sleep.svg` 已按仓库原件纳入为 `night.svg`；它因前一段未引用模板占号，在 HTML 内引用的是 `svg-template-27`。
- 不包含没有卡片引用的 HTML 内部模板 `svg-template-26`；这里的“26”是模板 ID，不是第 26 张有效卡片。

## Task 2：SVG 多变体与热加载

- assets 与 `/sdcard/Android/data/{pkg}/files/clawd_sprites/` 启动时扫描并合并。
- 文件名匹配完整状态 ID 或 `{状态ID}_` 前缀；重叠 ID 使用完整的最长状态 ID 归组。
- 切换时随机选取；池大小至少 2 时避免连续重复。
- 缺失状态回退 idle；0.2 秒 crossfade；angry/dizzy/dancing 使用规格动画。

## Task 3：完整状态仲裁

- 实现优先级表中的 28 个状态、优先级和远端解析。
- 高优先级立即覆盖；同级后触发覆盖。
- tap/双击/stuck_tap 具有 1.2 秒锁定和远端缓存。
- grabbed/stuck_grab 拖拽期间不可打断。
- dizzy/waving/clingy/morning 按 2/3/2/5 秒结束，并按 stuck → 远端 → 时段/孤独 → idle 回退。
- 气泡显示时自动 talking，消失后回前一状态；默认 4 秒、每 10 字加 1 秒、上限 10 秒。

## Task 4：尺寸、悬浮层与手势

- 螃蟹 90×90dp；气泡 180×120dp；设置范围 60–120dp、默认 90dp。
- 保持双悬浮层、气泡全触摸穿透、实时跟随、顶部下翻和水平防溢出。
- 实现 rawX/rawY、10dp 拖拽阈值、300ms 双击、500ms 长按菜单、fling/反弹。
- 松手中心距任一边 ≤15dp 时吸附；实现 grabbed/stuck/stuck_tap/stuck_grab 转换。

## Task 5：本地行为

- 实现规格内置四个时段的自言自语池及 5–15 分钟随机间隔。
- 实现 30/60/120/180 分钟孤独递进和互动重置。
- 实现 morning/eating/night/sleepy 时段行为。
- 使用 UsageStatsManager 每 5 秒感知前台 app，并映射 idle/peeking/waving 与上报事件。

## Task 6：Supabase 主备通信

- OkHttp 4.x WebSocket 订阅 `public.clawd_state` UPDATE，心跳并按 1/2/4/8/16/30 秒退避重连。
- WebSocket 失败时启用 5 秒 HTTP 轮询，恢复后停止轮询。
- GET/POST/WebSocket 均使用 publishable key；HTTP 同时带 `apikey` 与 `Authorization: Bearer`。
- `clawd_events` 攒满 3 条或 10 秒批量 POST；不修改数据库表结构或 RLS。

## Task 7：系统集成与设置

- 前台服务 START_STICKY，通知文字与“显示/隐藏”“退出”操作。
- BOOT_COMPLETED 自启及开关。
- 按悬浮窗 → 电池白名单 → 使用情况访问顺序引导，并说明原因。
- SharedPreferences 保存规格全部设置和 x/y 坐标，服务重启恢复位置并立即重连。

## Task 8：交付验证

- JVM 单测、真实浏览器 SVG/气泡验收、Manifest/Gradle/CI 静态检查。
- 构建并验证签名 release APK；push main 后 GitHub Actions 自动构建 artifact。
- README 只描述已实现且已验证的 v2 行为与配置。
